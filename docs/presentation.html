The gap

What Azure Boards did not give us

None of this is a defect in Azure DevOps. Boards is a work-item tracker, and it tracks work items very well. It is not a cross-team ageing dashboard, and every row below is a place where the team was doing that job by hand — or not doing it.

Scope
Four PODs, four tabs

On the board

Queries and widgets are scoped to a project and area path. Comparing four PODs meant four saved queries, opened side by side, each with its own idea of which work item types count.

In the tracker

One roll-up, every POD on it, sorted by whatever you care about. Any row expands in place to that POD’s own breakdown — from the same query that produced the row above it.

Ageing
Age was a date, not a number

On the board

A column showing Created Date. Turning “12 Mar” into “waited 34 days” is arithmetic somebody does in their head, per row, every time they look.

In the tracker

Age is computed at read time and bucketed — 0-3, 4-7, 8-14, 15-30, 30+ days. Never stored, because a stored age is wrong by tomorrow morning.

Urgency
One clock for every severity

On the board

“Old” was whatever each person decided it was. A Critical sitting for three days and a Minor sitting for three days looked identical in a query, so a board could either nag about Minors or stay quiet about Criticals — never neither.

In the tracker

An admin sets ageing per severity, per POD — Critical at two days while Minors get a fortnight. Across all PODs every item is judged by the board it came from, so the roll-up total is the sum of its rows. Where the PODs disagree, the tile says past each POD’s threshold rather than naming a number it cannot stand behind.

Vocabulary
Every board spells it differently

On the board

One POD writes 1 - Critical, another Blocker, a third P1. Three columns of the same thing that cannot be added together, so nobody added them.

In the tracker

Each board’s words resolve into one shared vocabulary — Critical, Major, Minor — per POD, with the POD’s own overrides winning. Anything unrecognised stays Unknown rather than being guessed into a bucket.

Environment
The field most boards never had

On the board

Most PODs have no environment field. Whether a bug came from IT-UAT, BIZ-UAT, CUG or production lived in a tag, or in the area path, or in the title, depending on who raised it.

In the tracker

Environment falls back through the field, then tags, then area path — because those are where teams actually put it. A real production count exists without anybody changing their process.

Closure
“Resolved” is not done

On the board

Azure stamps ResolvedDate the moment a developer moves a card, while QA still has it. Counting resolved as closed makes the burn-down look better than the release does.

In the tracker

Only ClosedDate closes an item, and a close date beats whatever the status text says. For QA Validation is its own visible state, not a rounding error.

Trust
A number you could not check

On the board

A widget says 31. The query behind it was written months ago by someone who has left. Opening it to see what 31 means is a five-minute detour, so nobody takes it.

In the tracker

Every number on screen is clickable and returns exactly that count. A test suite asserts the agreement for every tile, bar, row and chart point on every run.

Coverage
Teams that were not on Azure

On the board

A POD tracking work in a spreadsheet is simply absent from every Boards report — and absent reads as zero, which is the most expensive kind of wrong number.

In the tracker

Drag in an Excel, CSV or Apple Numbers export and that POD is on the same board as everyone else, under the same vocabulary. Re-upload after a correction — it updates rather than duplicating.

Access
All of it, or none of it

On the board

Area paths can be secured, but a cross-POD report is a project-level artefact — so the person who needed the comparison needed access to everything in it.

In the tracker

A member sees the PODs they are assigned to. Scoping is enforced on the server for every request — the POD picker in the UI is convenience, never the boundary.

Summary
No single honest figure

On the board

Plenty of counts, no headline. “Are we better than last month?” had no answer that survived being asked twice.

In the tracker

One health figure per POD, defined as the share of tracked items that are closed — arithmetic a reader can check against the two numbers printed beside it.

How it works

Three ways in, one shape, one query out

Whatever the source, everything is flattened into a single flat item document before it is stored. Every panel on the dashboard is then an aggregation over that one shape — which is what makes the numbers agree.

The score

Health, in one line of arithmetic

This started as a weighted heuristic — full marks less capped penalties for aged criticals, a stale average age and an open backlog. On the board above it read 32 where this reads 57, and nobody could reconstruct the gap without the source code.

health = round( closed ÷ total × 100 )   where closed = total − open
138 ÷ 244 × 100  →  57%

A score that has to be explained before it can be trusted is not doing its job on a dashboard. Age and severity are deliberately not in it — they sit beside the ring as Critical aged and Average age, where they are named and can be read directly. The score says how much is left; those two say how bad what is left has become.

Limits

What it refuses to do

Worth saying out loud, because each one is a place where a more impressive-looking dashboard would have quietly guessed.

Never invent a value

A severity it does not recognise stays Unknown. It never guesses which real one was meant, because a wrong value imported silently is worse than a visible gap.

Never trust a filename

An upload is identified by its bytes, not its extension. Whoever exported that file was not thinking about our parser.

Never score on age

Three criticals open for a quarter score the same as three trivial items raised this morning. That is the trade the simple formula makes, and the tiles beside it cover the difference.

Never widen a scope

A member assigned to no PODs gets a refusal, never an unscoped query. There is one place in the codebase where scope is decided.

To go live

Environment values, then deploy

The application is configured. Nothing else needs building — the remaining work is supplying real values and pointing it at the org.

Azure Organisation URL, project name, and a personal access token with Work Items (Read). Set per POD in Admin, or once in the environment for all of them.
Search An OpenSearch endpoint and credentials. Indices are created on first run — there is no migration step.
Sign-in Password accounts, Microsoft Entra ID SSO, or both. The first person to sign in with SSO becomes the administrator.
Secret A session signing secret of at least 32 characters. The app refuses to start in production without a real one, rather than falling back to a default that anyone reading the repository would know.
Live updates Optional. A webhook token gives instant updates from Azure; without it, the poller and the sync button still keep the board current.
